# 설계

이 문서는 FactLock이 어떻게 구성되는지 설명합니다. 만드는 사람과 심사하는 사람이 읽습니다.
2026-11-20에 구현했습니다. 구현하면서 달라진 점은 12절에 적었습니다.

## 1. 한눈에 보기

```
회사 자료·홈페이지 ──(AI가 읽음)──→ 사실 목록 ──┐
가이드라인 엑셀 ────(업로드)────→ 요구사항 ──┼→ 초안 만들기(AI) → 사실 잠금 검사 → 검수표 → 내려받기
타깃 선택 ──────→ 제품 묶음·예시 견적 ─────┘
붙여 넣은 글 ─────────────────────────────────────────→ 검수표
```

원칙은 하나입니다. **AI가 글을 쓰지만, 내보낼 수 있는지는 규칙이 정합니다.**

## 2. 계층

| 계층 | 폴더 | 들어가는 것 | 의존해도 되는 것 |
|---|---|---|---|
| 규칙 | `src/factlock/domain` | 사실, 타깃, 문장, 값 뽑기, 검수 규칙, 견적 계산 | 표준 라이브러리만 |
| 연결 약속 | `src/factlock/ports` | 사실 저장소, 가이드라인 읽기, 초안 작성기의 약속(Protocol) | `domain` |
| 업무 흐름 | `src/factlock/application` | 묶음 만들기, 초안 만들기, 글 검수 | `domain`, `ports` |
| 바깥 연결 | `src/factlock/adapters` | JSON·SQLite 저장, 엑셀 읽기, Claude API 호출 | 전부 |
| 서버와 화면 | `src/factlock/web` | FastAPI 경로, HTML 화면 | 전부 |

## 3. 데이터

회사마다 폴더 하나(`data/<회사>/`)를 둡니다. 다른 회사는 이 폴더만 새로 만들면 됩니다.

| 파일 | 내용 | 누가 만드나 |
|---|---|---|
| `facts.json` | 사실 목록 | Claude가 자료를 읽어 초안을 만들고 사람이 확인 |
| `targets.json` | 타깃과 제품 묶음 | Claude가 제안하고 담당자가 확인 |
| `guideline.json` | 가이드라인에서 읽은 요구사항과 강조 항목의 낱말 | 엑셀 업로드 + 사람이 확인 |
| `drafts/<타깃>.json` | 미리 만들어 둔 초안(연결이 끊겼을 때 사용) | Claude |

만든 초안과 검수 기록은 SQLite 파일(`var/factlock.db`)에 저장합니다.

### 3.1 사실 (Fact)

```json
{
  "id": "PRICE-A",
  "kind": "price",
  "statement": "A타입(고객관리 + 녹취 + 문자변환·요약 + 일일보고서)은 상담원당 월 30,000원입니다.",
  "values": [{"amount": 30000, "unit": "원"}],
  "anchors": ["A타입"],
  "source": {"where": "홈페이지 상담신청 페이지", "checked": "2026-11-20"},
  "scope": "기업용",
  "status": "confirmed",
  "requires": ["COND-VAT", "COND-ESTIMATE", "COND-MIN3"]
}
```

| 칸 | 뜻 |
|---|---|
| `kind` | `company`, `product`, `feature`, `number`, `price`, `condition`, `phrase` 중 하나 |
| `values` | 글에서 검사할 값. 금액·비율·개수를 숫자와 단위로 적음 |
| `anchors` | 이 사실을 가리키는 낱말. 문장에 이 낱말이 있으면 값이 맞는지 검사 |
| `status` | `confirmed`(확정), `conflict`(자료끼리 달라 확인 필요), `claim`(회사 주장) |
| `requires` | 이 사실을 쓰면 글에 함께 있어야 하는 조건의 번호 |

조건 사실은 `markers`를 가집니다. 글 전체에 이 중 하나가 있어야 조건을 지킨 것으로 봅니다.

```json
{"id": "COND-VAT", "kind": "condition", "statement": "가격은 부가세 별도입니다.",
 "markers": ["부가세 별도", "VAT 별도"], "status": "confirmed",
 "source": {"where": "홈페이지 상담신청 페이지", "checked": "2026-11-20"}}
```

상태별 쓰임새

| 상태 | 문구에 쓸 수 있나 |
|---|---|
| `confirmed` | 쓸 수 있음 |
| `conflict` | 쓸 수 없음. 담당자가 값을 정하면 `confirmed`로 바꿈 |
| `claim` | "회사 설명에 따르면"처럼 주장임이 드러날 때만 |

### 3.2 타깃 (Target)

```json
{
  "id": "field-sales",
  "name": "외근 영업 조직",
  "pains": ["PAIN-MOBILE-RECORD", "PAIN-NO-CRM-NOTE"],
  "bundle": ["PROD-MOBILE", "PROD-RECORDING", "PROD-CRM", "PROD-REPORT"],
  "quote_items": ["PRICE-A", "PRICE-REPORT"],
  "must_conditions": ["COND-ANDROID"],
  "status": "proposed"
}
```

- 묶음은 "추천 구성"이라고만 부릅니다. 없는 상품 이름을 만들지 않습니다.
- `status`가 `proposed`이면 화면에 "제안, 담당자 확인 전"이라고 표시합니다.
- 고민(`pains`)도 사실입니다. 회사 자료에 있는 문장만 씁니다.

### 3.3 가이드라인 (Guideline)

```json
{
  "required_keywords": ["통화요약", "콜센터 프로그램", "업무자동화"],
  "title_keywords": ["티링크 비즈레코딩", "영업사원 통화관리", "휴대폰 통화녹음", "인터넷전화 자동녹취"],
  "emphasis": [
    {"no": 3, "text": "통화가 끝나면 STT 문자변환, AI 통화요약 ... 자동으로 기록",
     "any_of": [["STT", "문자변환"], ["통화요약", "AI 요약"]], "terms_confirmed": true}
  ],
  "footer": ["www.tlinkcrm.com", "blog.naver.com/mobilecrm", "1877-3836"]
}
```

- 엑셀에서 항목은 규칙으로 읽습니다(칸 이름 `필수`, `서브`, `강조내용`, 번호 `1.`~`11.`).
- 강조 항목을 알아보는 낱말(`any_of`)은 묶음마다 하나 이상 글에 있어야 통과입니다.
- 낱말은 사람이 확인해야 합니다. 확인 전(`terms_confirmed: false`)에는 검수표에 "낱말 확인 필요"로 표시합니다.

### 3.4 초안 (Draft)

```json
{
  "title": "...",
  "blocks": [
    {"type": "sentence", "text": "A타입은 상담원당 월 30,000원입니다.", "fact_ids": ["PRICE-A"]},
    {"type": "sentence", "text": "이제 통화가 끝난 뒤를 살펴보겠습니다.", "fact_ids": []},
    {"type": "experience_slot", "hint": "직접 통화 한 건을 녹음하고 요약이 생기는 과정을 적는 칸"},
    {"type": "footer"}
  ],
  "source": "claude" 
}
```

| 블록 | 누가 채우나 |
|---|---|
| `sentence` | AI. 근거 사실 번호가 붙음 |
| `experience_slot` | **사람.** AI는 체험을 지어내지 않고 빈칸으로 둠. 채우기 전에는 검수에서 실패 |
| `footer` | 규칙. 사실 목록의 연락처로 만듦 |

## 4. 값 뽑기

글에서 검사할 값을 뽑아 같은 모양으로 맞춥니다.

| 종류 | 글에 쓰인 모습 | 맞춘 값 |
|---|---|---|
| 금액 | `30,000원`, `3만 원`, `30만원` | 30000원, 30000원, 300000원 |
| 비율 | `99%`, `23 %` | 99%, 23% |
| 개수 | `1,000여 개`, `3,000석`, `115건`, `3명` | 숫자와 단위 |
| 제품명 | 사실의 `anchors`와 같은 낱말 | 사실 번호 |

검사하지 않는 것: 날짜, 목차 번호(`1.`, `01`), 전화번호와 주소(하단 정보 규칙이 따로 검사).

## 5. 사실 잠금 검사 (초안)

AI가 쓴 문장마다 아래를 검사합니다.

| 검사 | 실패하면 |
|---|---|
| 문장의 값이 모두 근거 사실의 `values`에 있음 | 문장을 빼고 "근거에 없는 값"으로 기록 |
| 문장의 제품명이 근거 사실이나 타깃 묶음에 속함 | 문장을 뺌 |
| 근거 사실이 `confirmed`임 (`claim`이면 주장 표현이 있음) | 문장을 뺌 |
| 근거가 없는 문장에 값·제품명·최상급이 없음 | 문장을 뺌 |

빠진 문장은 화면에 이유와 함께 보여 줍니다. 조용히 지우지 않습니다.

## 6. 검수 규칙 (만든 글과 붙여 넣은 글 공통)

| 번호 | 규칙 | 실패하는 경우 |
|---|---|---|
| R1 | 필수 키워드 | 제목 또는 본문에 필수 키워드가 없음 |
| R2 | 강조 항목 | 강조 항목 중 낱말 묶음을 채우지 못한 것이 있음 |
| R3 | 하단 정보 | 홈페이지, 블로그, 상담 번호 중 빠진 것이 있음 |
| R4 | 자료와 다른 값 | 문장에 사실의 `anchors`가 있는데 같은 단위의 값이 사실과 다름 |
| R5 | 목록에 없는 값 | 금액·비율·개수가 어떤 확정 사실에도 없음 |
| R6 | 확인 필요 값 | `conflict` 사실의 값을 씀 |
| R7 | 필수 조건 | 쓴 사실의 `requires` 조건이나 타깃의 필수 조건이 글에 없음 |
| R8 | 남은 작업 메모 | `[이미지 삽입: ...]`, 비어 있는 체험 칸, `TODO` 등이 남음 |
| R9 | 최상급·비교 | 근거 없는 `최고`, `유일`, `업계 최저`, `100%` 등 |
| R10 | 광고 표시 | 협찬·광고 표시 문구가 없음. 실패가 아니라 "담당자 확인"으로 표시 |

결과는 규칙마다 `통과` / `실패` / `확인 필요`와 문제가 된 문장, 관련 사실 번호를 돌려줍니다.

**규칙 검수의 한계**: 낱말과 숫자를 대조하는 방식이라, 숫자 없이 뜻만 틀린 문장은 잡지 못합니다.
맞는 값을 다른 상품 옆에 쓴 경우는 R4가 `anchors`로 잡지만 모든 경우를 잡지는 못합니다. 이 한계를 화면과 발표에서 밝힙니다.

## 7. 견적 계산

```
월 비용   = Σ (상담원당 요금 × 인원) + Σ (정액 요금)
최초 설정비 = Σ (항목별 설정비)
```

- 금액은 정수(원)로 계산합니다.
- 인원이 최소 인원(3명)보다 적으면 계산하지 않고 이유를 알려 줍니다.
- 결과에는 항상 "예시 견적, 부가세 별도, 상담 후 확정" 조건과 계산식이 함께 나옵니다.
- 자료만으로 알 수 없는 항목(휴대폰 연동 요금과 타입 요금의 관계)은 더하지 않고 "확인 필요"로 표시합니다.

## 8. 서버 기능

| 경로 | 받는 것 | 돌려주는 것 |
|---|---|---|
| `GET /api/facts` | 없음 | 사실 목록(상태·출처 포함) |
| `GET /api/targets` | 없음 | 타깃 목록 |
| `POST /api/bundle` | 타깃, 인원 | 묶음 구성, 고민, 견적 줄, 조건 |
| `POST /api/guideline` | 엑셀 파일 | 읽은 요구사항, 확인이 필요한 낱말 |
| `POST /api/drafts` | 타깃 | 초안 블록, 빠진 문장과 이유, 검수표, 초안 출처(`claude` / `stored`) |
| `POST /api/review` | 제목, 본문, 타깃(선택) | 검수표 |
| `GET /api/drafts/{id}/export` | 없음 | 글 파일(`.md`)과 검수표 |

오류는 고정된 코드와 한국어 안내로 돌려줍니다. 올린 내용이나 키를 오류 문구에 넣지 않습니다.

## 9. 연결 약속 (ports)

```python
class FactRepository(Protocol):
    def all(self) -> list[Fact]: ...
    def get(self, fact_id: str) -> Fact | None: ...


class TargetRepository(Protocol):
    def all(self) -> list[Target]: ...
    def get(self, target_id: str) -> Target | None: ...


class GuidelineReader(Protocol):
    def read(self, data: bytes) -> Guideline: ...


class DraftWriter(Protocol):
    def write(self, request: DraftRequest) -> Draft: ...


class DraftStore(Protocol):
    def save(self, draft: Draft, report: ReviewReport) -> str: ...
    def load(self, draft_id: str) -> tuple[Draft, ReviewReport] | None: ...
```

`DraftWriter`의 구현은 둘입니다.

| 구현 | 하는 일 | 언제 |
|---|---|---|
| `ClaudeDraftWriter` | Claude API에 쓸 수 있는 사실과 가이드라인을 보내고, 문장과 사실 번호를 JSON으로 받음 | API 키가 있고 연결될 때 |
| `StoredDraftWriter` | `drafts/<타깃>.json`을 읽음 | 키가 없거나 연결이 끊겼을 때, 테스트 |

Claude API로는 **사실 목록과 가이드라인만** 보냅니다. 올린 글이나 개인정보는 보내지 않습니다.

## 10. 검증

만들기 전에 정답 사례를 먼저 테스트로 씁니다. 글은 실제 글의 형식만 본뜬 합성 글입니다.

| 번호 | 입력 | 기대 결과 |
|---|---|---|
| C1 | 사실 목록 안에서 쓴 글 | R1~R9 통과, R10 확인 필요 |
| C2 | "A타입 설정비 20만 원"이 든 글 | R4 실패, 해당 문장과 설정비 사실(`SETUP-TYPE`, 300,000원) 표시 |
| C3 | `[이미지 삽입: ...]`이 3번 든 글 | R8 실패, 3건 |
| C4 | 가격만 있고 부가세 별도가 없는 글 | R7 실패, `COND-VAT` 표시 |
| C5 | "학교 200여 곳"이 든 글 | R6 실패(확인 필요 값) |
| C6 | 휴대폰 녹취를 말하고 아이폰 조건이 없는 글 | R7 실패, `COND-ANDROID` 표시 |
| C7 | 근거 번호와 값이 다른 AI 문장 | 문장이 빠지고 이유가 기록됨 |
| C8 | A타입 5명 + 종합리포트 견적 | 월 250,000원, 설정비 300,000원, 조건 세 가지 |
| C9 | A타입 2명 견적 | 계산하지 않고 최소 3명 안내 |
| C10 | 체험 칸이 빈 초안 | R8 실패 |

## 11. 만드는 순서와 나누기

| 순서 | 일 | 맡는 쪽 | 건드리는 곳 |
|---|---|---|---|
| 1 | 데이터 모양, 연결 약속, 정답 사례 테스트 | Claude | `domain/models`, `ports/`, `tests/` |
| 2 | `facts.json`, `targets.json`, `guideline.json` 작성 | Claude | `data/tlink/` |
| 3a | 값 뽑기, 검수 규칙, 사실 잠금, 견적 | Claude | `domain/` |

| 4 | 화면 시안 3개 → 선택 → 화면 | Claude | `web/static` |
| 5 | Claude API 연결(승인 후), 저장된 초안 | Claude | `adapters/` |
| 6 | 전체 검증, 시연 연습 | Claude | |

1번이 끝나야 3a와 3b를 동시에 할 수 있습니다.

## 12. 구현하면서 달라진 점과 남은 것

달라진 점
- 가이드라인에 `targets`(이 가이드라인이 겨냥한 타깃)를 더했습니다. 다른 타깃의 글에는 강조 항목 검사(R2)를 하지 않고 '확인 필요'로 알립니다. 티링크 가이드라인은 '외근 영업 조직'용입니다.
- 설정비는 타입 요금과 따로 `PRICE-SETUP` 사실로 두었습니다. "A타입 설정비 20만 원"처럼 여러 사실이 걸린 문장은 걸린 사실들의 값을 합쳐서 대조합니다.
- 화면은 시안 3개 중 단계형(A)으로 만들었습니다. '받은 글 검수'와 '사실 목록'은 단계 옆의 별도 화면입니다.
- 초안 블록에 `heading`(소제목)을 더했습니다. 소제목에도 사실 잠금 검사를 합니다.

남은 것

| 남은 것 | 누가 | 지금은 |
