# 설계

이 문서는 FactLock이 어떻게 구성되는지 설명합니다. 만드는 사람과 심사하는 사람이 읽습니다.
**아직 구현 전의 설계입니다.** 구현하면서 달라진 점은 이 문서에 고쳐 적습니다.

## 1. 한눈에 보기

```
회사 자료·홈페이지 ──(AI가 읽음)──→ 사실 목록 ──┐
가이드라인 엑셀 ────(업로드)────→ 요구사항 ──┼→ 초안 만들기(AI) → 사실 잠금 검사 → 검수표 → 내려받기
타깃 선택 ──────→ 제품 묶음·예시 견적 ─────┘
붙여 넣은 글 ─────────────────────────────────────────→ 검수표
```

AI가 글을 쓰지만, 내보낼 수 있는지는 규칙이 정합니다.

## 2. 계층

| 계층 | 폴더 | 들어가는 것 | 의존해도 되는 것 |
|---|---|---|---|
| 규칙 | `src/factlock/domain` | 사실, 타깃, 문장, 검수 규칙, 견적 계산 | 표준 라이브러리만 |
| 연결 약속 | `src/factlock/ports` | 사실 저장소, 가이드라인 읽기, 초안 작성기의 약속(Protocol) | `domain` |
| 업무 흐름 | `src/factlock/application` | 묶음 만들기, 초안 만들기, 글 검수 | `domain`, `ports` |
| 바깥 연결 | `src/factlock/adapters` | 파일·DB 저장, 엑셀 읽기, Claude API 호출 | 전부 |
| 서버와 화면 | `src/factlock/web` | FastAPI 경로, HTML 화면 | 전부 |

## 3. 핵심 데이터

### 사실 (Fact)

| 칸 | 뜻 | 예 |
|---|---|---|
| `id` | 번호 | `PRICE-A` |
| `statement` | 사실을 적은 문장 | A타입은 상담원당 월 30,000원입니다 |
| `values` | 문장 속에서 검사할 값 | `30,000원` |
| `source` | 출처 | 홈페이지 상담신청 페이지 |
| `scope` | 적용 범위 | 기업용 |
| `status` | 상태 | `confirmed`(확정), `conflict`(확인 필요), `claim`(회사 주장) |
| `conditions` | 함께 써야 하는 조건의 사실 번호 | `COND-VAT`, `COND-ESTIMATE` |

- `conflict` 상태의 사실은 문구에 쓸 수 없습니다.
- `claim` 상태의 사실은 "회사 설명에 따르면"처럼 주장임이 드러나게만 씁니다.

### 타깃 (Target)

이름, 고민(사실 번호), 제품 묶음, 반드시 넣을 조건으로 이루어집니다.
묶음은 "추천 구성"이라고만 부릅니다. 없는 상품 이름을 만들지 않습니다.

### 가이드라인 (Guideline)

엑셀에서 읽은 필수 키워드, 강조 항목과 각 항목을 알아보는 낱말, 하단 필수 정보입니다.

### 초안 문장 (Sentence)

글과 근거 사실 번호 목록입니다. 근거가 없는 문장은 숫자·가격·제품명을 담을 수 없습니다.

## 4. 사실 잠금 검사

1. AI에게 쓸 수 있는 사실 목록을 주고, 문장마다 근거 사실 번호를 붙여 답하게 합니다.
2. 문장에서 숫자, 가격, 비율, 제품명을 뽑습니다.
3. 뽑은 값이 근거 사실의 `values`에 있는지 봅니다.
4. 없으면 그 문장을 빼고 이유를 남깁니다.
5. 사실에 조건이 있는데 글 전체에 그 조건이 없으면 실패로 표시합니다.

## 5. 검수 규칙

| 규칙 | 실패하는 경우 |
|---|---|
| 필수 키워드 | 제목 또는 본문에 필수 키워드가 없음 |
| 강조 항목 | 가이드라인의 강조 항목 중 빠진 것이 있음 |
| 하단 정보 | 홈페이지, 블로그, 상담 번호가 없음 |
| 숫자 불일치 | 글의 숫자가 사실 목록의 값과 다름 |
| 확인 필요 사실 | '확인 필요' 상태의 값을 씀 |
| 필수 조건 | 가격을 말했는데 부가세 별도·예시 견적이 없음 등 |
| 남은 작업 메모 | `[이미지 삽입: ...]` 같은 메모가 남아 있음 |
| 최상급·비교 | 근거 없는 '최고', '유일', '업계 최저' |
| 광고 표시 | 협찬·광고 표시가 없음 (담당자 확인 항목으로 표시) |

검수 결과는 규칙마다 통과·실패와, 문제가 된 문장을 함께 보여 줍니다.

## 6. 서버 기능

| 경로 | 하는 일 |
|---|---|
| `GET /api/facts` | 사실 목록 |
| `GET /api/targets` | 타깃 목록 |
| `POST /api/bundle` | 타깃과 인원으로 묶음과 예시 견적 계산 |
| `POST /api/guideline` | 가이드라인 엑셀 업로드와 확인 |
| `POST /api/drafts` | 초안 만들기와 사실 잠금 검사 |
| `POST /api/review` | 붙여 넣은 글 검수 |

## 7. AI 연결과 시연 안전

- 초안 작성기는 약속(Protocol) 하나로 두고 구현을 둘 만듭니다.
  - Claude API를 부르는 구현
  - 미리 만들어 저장해 둔 초안을 돌려주는 구현
- API 키가 없거나 연결이 끊기면 저장된 초안을 쓰고, 화면에 "저장된 초안"이라고 표시합니다.
- 검수와 견적 계산은 AI 없이 동작합니다.
- 테스트는 가짜 초안 작성기로 실행하고 네트워크를 쓰지 않습니다.

## 8. 검증

만들기 전에 정답 사례를 먼저 정합니다.

| 사례 | 입력 | 기대 결과 |
|---|---|---|
| 통과하는 글 | 사실 목록 안에서 쓴 합성 글 | 모든 규칙 통과 |
| 가격이 다른 글 | 설정비를 다르게 쓴 합성 글 | 숫자 불일치 실패, 해당 문장 표시 |
| 작업 메모가 남은 글 | `[이미지 삽입: ...]`이 든 합성 글 | 남은 작업 메모 실패, 개수 표시 |
| 조건이 빠진 글 | 가격만 있고 부가세 별도가 없는 합성 글 | 필수 조건 실패 |
| 견적 계산 | A타입 5명 + 종합리포트 | 월 250,000원, 설정비 300,000원, 조건 표시 |

정답 사례의 글은 실제 글의 형식만 본뜬 합성 글로 만듭니다.

## 9. 아직 정하지 않은 것

- 화면 구성: 방향이 다른 시안 3개를 만들고 고릅니다.
- 화면 안에서 Claude API를 실시간으로 부를지: 사실 목록이 외부로 나가므로 사용자 승인이 필요합니다.
- 타깃별 묶음 구성: 제안이므로 티링크 담당자의 확인이 필요합니다.
