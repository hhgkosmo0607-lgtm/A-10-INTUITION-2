# 1단계 기획서 (Track A, 티링크)

칸마다 그대로 복사해 붙여 넣습니다. 숫자는 모두 2026-11-20에 티링크 자료·홈페이지·공식 블로그에서 직접 확인한 값입니다.

## [프로젝트명]

A-10-INTUITION(2) 프로젝트

## [한 줄 소개]

타깃을 고르면 회사 자료에 있는 사실만으로 제품 묶음과 광고 글을 만들고, 내보내기 전에 자료와 다른 숫자·빠진 조건을 자동으로 검수하는 도구

## [대상 사용자]

제품이 여러 개인데 전담 마케터가 없는 소규모 B2B 기업의 홍보 담당자. 첫 사용자는 상주 인원 7명으로 홈페이지 메뉴 기준 9가지 통신·녹취 서비스를 파는 티링크의 담당자입니다. 블로그 글과 리뷰 가이드라인을 관리하는 사람입니다.

## [해결하려는 문제]

티링크의 자료, 홈페이지 20개 페이지, 공식 블로그 글 38개를 모두 읽고 확인한 문제입니다.

1. 제품이 9가지라 글마다 무엇을 누구에게 말하는지 흩어집니다. 가이드라인의 제품명 '티링크 비즈레코딩'은 홈페이지의 보이는 글에는 없고, 이미지 설명에만 두 번 나옵니다.
2. 글마다 숫자가 다릅니다. 고객관리 서비스의 초기 비용이 블로그 글에는 '설치비 20만 원', 홈페이지 견적에는 '설정비 30만 원'으로 적혀 있어 읽는 사람은 어느 쪽이 맞는지 알 수 없습니다. 학교 실적도 페이지에 따라 '150여 개'와 '200여 개'로 다릅니다.
3. 검수 없이 게시됩니다. 2026년 10월 블로그 글 1개에 "[이미지 삽입: ...]"이라는 작업 메모가 3군데 남아 있습니다.
4. 리뷰 가이드라인은 필수 키워드 3개와 강조 내용 11가지를 요구하는데, 받은 글이 이를 지켰는지는 사람이 눈으로 대조해야 합니다.
5. 꾸준히 만들기 어렵습니다. 블로그는 2025년 1월 이후 약 20개월 동안 새 글이 없다가 2026년 9~11월에 10개가 올라왔습니다.

글쓰기를 AI에 그대로 맡기면 문장은 나오지만, 회사 자료와 맞는지는 사람이 따로 확인해야 합니다. 검수에 드는 시간은 아직 재지 못했습니다. 담당자에게 확인해 2단계에서 밝히겠습니다.

## [해결 방법]

AI는 세 곳에 씁니다. 틀리면 안 되는 검수는 AI가 아니라 규칙으로 합니다.

1. 자료 읽기(AI): Claude가 회사 자료, 홈페이지, 블로그를 읽어 가격·숫자·기능·조건을 출처와 함께 '사실 목록'으로 정리합니다. 자료끼리 값이 다르면 고르지 않고 '확인 필요'로 잠급니다.
2. 타깃별 묶음(AI + 사람 확인): 타깃을 고르면 Claude가 사실 목록에서 그 타깃에 맞는 제품 묶음, 타깃의 고민, 예시 견적을 뽑고 담당자가 확인합니다. 예: '외근 영업 조직'이면 휴대폰 녹취, 통화요약, 고객관리, 종합리포트.
3. 글 만들기(AI + 규칙): Claude가 사실 목록 안에서만 블로그 초안을 쓰고 문장마다 근거 사실 번호를 붙입니다. 서버가 문장 속 숫자·가격·제품명을 그 사실과 대조해, 맞지 않는 문장은 빼고 이유를 보여 줍니다. 가격에는 '예시 견적·부가세 별도', 휴대폰 녹취에는 '아이폰 불가' 같은 조건이 따라붙습니다.
4. 검수(규칙): 내보내기 전에 필수 키워드, 강조 내용 11가지, 하단 문의 정보, 자료와 다른 숫자, 남은 작업 메모, 근거 없는 최상급 표현을 검사해 통과·실패 표로 보여 줍니다. 외부에서 받은 글도 같은 표로 검사합니다.

실제 게시와 발송은 사람이 합니다.

## [주요 기능]

핵심 기능 3개
1. 사실 목록과 타깃별 제품 묶음: 가격·숫자·조건을 출처와 함께 보여 주고, 타깃을 고르면 묶음 구성과 예시 견적을 표시
2. 사실 기반 블로그 초안: 가이드라인 엑셀을 올리면 문장마다 출처가 붙은 초안 생성
3. 자동 검수표: 만든 글과 붙여 넣은 글을 같은 기준으로 검사(키워드, 강조 내용, 필수 조건, 숫자 불일치, 남은 작업 메모)

MVP 범위: 티링크 한 회사, 타깃 2개('외근 영업 조직', '재택 콜센터'), 채널은 블로그 하나

제외한 기능: 블로그·SNS 자동 게시, 문자 자동 발송, 이미지·영상 제작, 인스타그램·문자용 변환, 광고 관련 법률 판단(담당자 확인 항목으로만 표시)

## [기술 스택]

AI 모델: Claude와 Codex (구독 CLI 또는 Claude API로 연결. 묶음 고르기, 초안 작성, 의미 검수에 사용)
백엔드: Python 3.12, FastAPI, SQLite, 엑셀 읽기(openpyxl)
검수 엔진: 순수 Python 규칙(사실 잠금 검사, 키워드·조건 검사, 견적 계산), pytest로 정답 사례 검증
화면: HTML·JavaScript
공개: GitHub
